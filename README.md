# YesPOS интеграционный сервис

Отдельный сервис, который держит одну залогиненную Playwright-сессию
в YesPOS и создаёт клиентов по запросу от Telegram-бота.

## Почему отдельный сервис, а не прямо в боте

- Если YesPOS поменяет вёрстку или сайт зависнет — сломается только
  создание карточек лояльности, а не весь бот (регистрация в Excel
  продолжит работать).
- Браузер логинится один раз и держит сессию, а не перелогинивается
  на каждого клиента (быстрее и надёжнее).
- Заявки обрабатываются по очереди, без риска, что два клиента
  создаются одновременно в одном браузере и путают друг друга.

## Установка

```bash
cd yespos_service
pip install fastapi uvicorn playwright aiohttp
playwright install chromium
```

## Настройка

**Секретные данные хранятся только в переменных окружения — не в коде.**

Локально: скопируйте `.env.example` в `.env` и заполните реальными данными:
```bash
cp .env.example .env
# отредактируйте .env своим текстовым редактором
```

На Railway: переменные задаются в **Settings → Variables** сервиса,
`.env` файл туда заливать не нужно (он и так в `.gitignore`, чтобы
случайно не попал в GitHub).

Нужные переменные:
```
YESPOS_ORG_ID=51844471
YESPOS_LOGIN=hamidulloh12
YESPOS_PASSWORD=hamidulloh12
YESPOS_HEADLESS=true
```

Если хотя бы одна из `YESPOS_ORG_ID` / `YESPOS_LOGIN` / `YESPOS_PASSWORD`
не задана — сервис не запустится и выдаст понятную ошибку вместо того,
чтобы тихо использовать неправильные данные.

## Запуск сервиса

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

Проверить что работает:
```bash
curl http://localhost:8000/health
```

## Интеграция с ботом

В коде бота (там, где сохраняете пользователя в Excel), добавьте
вызов из `bot_integration_example.py`:

```python
from bot_integration_example import register_client_in_yespos

# после сохранения в Excel:
await register_client_in_yespos(
    name=user_name,
    phone=user_phone,
    birth_date=user_birth_date,  # "15.03.1995" или ""
    gender=user_gender,          # "Erkak"/"Ayol" или ""
)
```

Это не блокирует и не ломает бота, если сервис недоступен —
просто пишет в лог и возвращает False.

## Важно перед продакшеном

1. **Уберите HEADLESS=false тест** — в проде держите `YESPOS_HEADLESS=true`.
2. **Пароли** — сейчас лежат как есть в примере, для продакшена вынесите
   в `.env` файл и никогда не коммитьте в git.
3. **Что если YesPOS изменит вёрстку** — селекторы в `yespos_client.py`
   привязаны к конкретным `name`/`id` атрибутам полей. Если YesPOS
   обновит фронтенд, часть селекторов может перестать работать —
   тогда нужно будет повторить процесс "найти новый селектор" как
   мы делали при разработке.
4. **Мониторинг** — стоит настроить, чтобы при ошибках создания клиента
   (`{"success": False, ...}`) вам приходило уведомление (например,
   в отдельный Telegram-чат для админов), а не терялось в логах.
5. **Запуск как автономный процесс** — используйте `systemd` (Linux) или
   `NSSM`/Task Scheduler (Windows) чтобы сервис поднимался автоматически
   и перезапускался при падении.
